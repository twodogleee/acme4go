# 统一凭据管理

原“DNS 凭据”和云部署中的“云账号”统一进入“凭据管理”。页面路径为 `/credentials`，原 `/dns-credentials` 自动跳转。云部署页面只选择已启用相应用途的凭据。

## 用途与权限

一条凭据只保存一份加密访问密钥，可以选择：

- **DNS 验证**：填写根域名，用于签发时创建和清理 DNS TXT 记录。支持阿里云和 Cloudflare。
- **云部署**：用于阿里云证书中心查询、上传以及 OSS/CDN 部署。只有该用途时，根域名可以留空。
- **同时使用**：阿里云密钥在同一条凭据上勾选两个用途，DNS 与云部署直接读取共享秘密。

用途开关限定 Acme4go 是否可以使用凭据，不会授予阿里云或 Cloudflare 的权限。DNS 权限验证会创建并清理测试 TXT 记录；“查看云证书”验证证书中心查询权限，不代表具备 OSS/CDN 的写入权限，产品权限在实际任务中检查。

关闭一种用途不会关闭另一种用途。停用整条凭据会停止两个用途的后续使用。更新共享秘密会同时影响所有引用该凭据的用途；正在执行云任务时禁止修改凭据。编辑时秘密留空保留原值，响应不返回秘密或密文。

已经启用过云部署用途的 AccessKeyId 不可原地更换，避免把历史云证书 ID 用于另一个身份。更换 AccessKeyId 时新增凭据，再显式调整引用。Secret 字段可在原条目中更新。

## 数据模型与已有 DNS 数据

云账号尚未投入使用，本实现直接采用统一凭据模型，不提供旧云账号迁移或旧云账号管理接口。

- 保留已有 DNS 凭据的主键、加密密钥、证书系列及订单引用，默认开启 DNS 用途、关闭云部署用途。
- 上传规则、部署目标和上传记录直接通过 `credential_id` 引用共享凭据，没有独立云账号表或账号 ID 映射。
- 所有用途使用同一份加密密钥。为兼容已使用的 DNS 数据，沿用原加密上下文和 `dns_credentials` 表名。
- 版本 9 为现有凭据增加用途字段与云身份唯一约束；启用云用途后固定 AccessKeyId，停用该用途也不会解除身份保护。
- 版本 10 修复早期版本已创建但未使用的旧云表：检查云账号、配置、上传记录及任务均为空后，在事务中重建为直接引用统一凭据的结构，并补齐初版版本 9 可能缺少的身份字段。已有新模型云数据保持不变；若旧云表存在数据，则保留数据并明确中止升级，不自动清空或猜测账号映射。
- 删除凭据时由外键保护 DNS 与云资源的引用；被引用的凭据可以停用，不能直接删除。

## API

统一维护接口为 `GET/POST /api/credentials`、`PUT/DELETE /api/credentials/{id}`。输入包含 `dnsEnabled` 和 `cloudEnabled`，至少选择一种用途。云配置直接使用 `credentialId`，查询云证书使用 `GET /api/credentials/{id}/cloud-certificates`。

原 DNS 接口继续保留，列表只返回具有 DNS 用途的条目。通过旧 DNS 接口更新共享凭据也会经过云任务保护。新客户端使用统一接口明确选择用途。

更新 Server 后自动扩展已有 DNS 凭据表并初始化云部署表。此变更不修改 Agent 协议，Agent 无需访问这些云凭据。

如果旧 Server 日志持续出现 `扫描云配置失败` / `no such column: credential_id`，说明旧云建表迁移已经登记，但表仍使用 `account_id`。需更新包含版本 10 修复的 Server 后重启，刷新网页或只重启旧版本不会改变表结构。不需要删除整个数据库，也不要手动将 `account_id` 改名：两种 ID 引用的实体和外键不同。
