# 架构说明

## 组件边界

Acme4go 的控制平面是模块化单体，不把一个小规模证书系统拆成需要独立运维的微服务。模块间通过 Go 接口与显式领域对象协作，共用单个 SQLite 数据库，但外部网络边界严格分离。

```text
cmd/acme4go
├── server
│   ├── control.AdminHandler  :8080  管理 API + 嵌入式 Vue SPA
│   ├── control.AgentHandler  :9443  HTTPS / mTLS Agent API
│   ├── app.Services                 领域编排、续期调度、有界任务执行
│   ├── acmeissuer                   lego + DNS-01
│   ├── store                        SQLite / Schema / 事务
│   ├── cryptoutil                   Argon2id / AES-GCM / Token 摘要
│   ├── pki                          独立 Agent CA 与身份签发
│   └── deploy                       加密证书库与原子文件物化
└── agent
    ├── 一次性 Join URL 注册
    ├── mTLS 心跳与期望状态拉取
    ├── 证书材料完整性验证
    └── 加密缓存与原子 PEM 物化
```

## 为什么控制平面与 Agent 逻辑分离、交付不分裂

控制平面持有 DNS 凭据、ACME 账户、证书库和管理员会话，安全权限较高；Agent 只拿到自己被授权的证书并在业务主机落地。二者权限和运行生命周期不同，因此必须是两种运行角色。

但它们共享大量证书解析、加密、配置和文件物化代码。拆成两个仓库或镜像会增加版本匹配、发布和部署负担，所以使用同一个 `acme4go` 二进制，通过第一个参数选择角色。这同时保证：

- 发布时只构建和签名一个制品；
- 用户只记住一个镜像名；
- Agent 升级与控制面升级使用相同版本语义；
- Server 默认启用本机执行器，用户无需引入第三种运行角色即可完成单节点部署。

运行角色、能力和拓扑是三个不同维度：

- 角色只有 `server` 与 `agent`，决定进程的安全边界和生命周期；
- `ACME_LOCAL_DEPLOYMENT_ENABLED` 是 Server 能力开关，决定是否允许本机证书物化；
- 单节点、混合部署、纯控制平面是由角色与能力组合出来的拓扑，不是新的命令。

部署目标使用显式 `executor_type`：`LOCAL` 表示 Server 本机执行器，`AGENT` 表示指定远程 Agent。`agent_id` 只负责关联 Agent 身份，不再通过空值隐式猜测目标类型。

## 数据与状态

控制平面是唯一权威状态源。SQLite 保存管理员、会话摘要、加密 DNS 凭据、ACME 账户、证书元数据、订单、Agent 身份、部署目标、部署结果和审计日志。

数据库结构采用带版本记录的 Go 启动迁移机制。`internal/store/schema.sql` 是新数据库完整结构的唯一权威来源，由 `go:embed` 编入 Server；`store.Open()` 先应用这份幂等 Schema，再读取 `schema_migrations` 并按版本顺序执行尚未成功记录的 Go 迁移。迁移完整成功后才记录版本，失败会阻止 Server 启动；迁移函数仍保持幂等，以覆盖迁移成功后、版本落库前进程退出的恢复窗口。迁移版本不可复用，旧二进制会拒绝打开已经由更高版本升级的数据库，避免不兼容回退损坏数据。最新数据库重复启动只读取少量版本和索引元数据，并通过索引友好的查询检查异常旧数据，不再全表归并历史数据或重建唯一索引。`migrations` 目录只保留早期 SQL 历史快照，运行时不会扫描或执行。每次结构变更都必须同时更新完整 Schema 和旧库 Go 迁移，并验证新库初始化、旧库升级、失败恢复以及重复启动。SQLite 不保存字段 `COMMENT` 元数据，因此表、字段、约束和索引说明维护在 `schema.sql` 源码注释中。

证书业务身份使用稳定的 `certificate_series.id`。相同 CA 下的同一无序域名组合归入同一个系列，订单和每次签发产生的物理证书都引用该系列；版本号在系列内递增，系列通过 `current_certificate_id` 指向当前版本。部署目标人工选择并保存 `certificate_series_id`，续期、Server 部署、Agent 期望状态、证书下载授权与部署回执都按系列 ID 校验，不使用域名字符串猜测关联关系。旧数据库升级时会自动归并历史证书；无法唯一判断的旧部署目标进入 `NEEDS_BINDING` 状态，等待管理员重新选择。

Agent 保存：

- 内部 CA、客户端证书及客户端私钥；
- 32 字节本地随机主密钥；
- 从控制面取得的加密证书缓存；
- 已应用目标的 `revision:fingerprint:alias` 状态。

Agent 不维护可被编辑的第二份业务数据库。每次轮询都以控制面的期望状态为准，因此断网恢复后会自动收敛。

## 证书签发时序

1. 管理员提交域名、邮箱、CA 环境和 DNS 凭据。
2. 控制面规范化域名并持久化 `QUEUED` 订单。
3. 有界后台执行器最多并发处理两个订单。
4. 加载或创建与邮箱、CA 目录绑定的持久 ACME 账户。
5. lego 根据凭据类型使用阿里云或 Cloudflare DNS Provider 完成 DNS-01。
6. 解析并校验证书，计算叶证书 SHA-256 指纹。
7. 证书和证书链落盘；私钥使用用途绑定 AES-256-GCM 加密后落盘。
8. 插入不可变证书版本并完成订单。
9. 启用本机执行器的 Server 立即对账 `LOCAL` 目标；远程 Agent 在下一次轮询时收敛 `AGENT` 目标。

服务重启时，未完成订单会被标记失败，避免在不确定外部 ACME 状态下盲目续跑。用户可从失败记录显式重试。

## Agent 注册与轮询

1. 管理员生成 10 分钟有效的一次性令牌；数据库只保存 SHA-256 摘要。
2. 控制面把公开 Agent URL、原始一次性令牌和内部 CA PEM 封装为 Join URL。
3. Agent 自己生成 P-256 私钥和 CSR，通过内部 CA 校验服务端后注册。
4. 控制面消费令牌、创建 UUID 身份并签发 180 天客户端证书。
5. 后续请求均使用 TLS 1.3 mTLS；应用层再验证证书序列号、Agent UUID 和启用状态。
6. 客户端证书到期前 30 天，Agent 用原私钥生成新 CSR并自动续签。控制面保留一个旧序列号作为写盘故障恢复窗口。
7. Agent 拉取目标期望状态，只有目标明确分配给当前 Agent 时才能下载证书。
8. Agent 验证指纹、SAN、有效期及公私钥匹配后再部署并上报结果。

## 一致性选择

- 控制平面数据库写入使用 SQLite 单写连接与事务。
- 证书版本以指纹目录不可变保存。
- 文件部署先完整写入新目录并 `fsync`，最后以同文件系统 `rename` 切换符号链接。
- 失败不会主动删除旧版本或当前链接。
- 删除部署目标只删除控制面配置，不删除业务服务器文件。
- Agent 被撤销后停止获得新状态，但既有业务证书继续工作，避免控制面操作直接造成业务中断。

## 扩展点

- DNS Provider：在应用输入层增加 Provider 类型，并向 `acmeissuer` 注入对应 lego Provider。
- 存储：`store` 当前针对 SQLite 优化。只有明确需要多控制平面高可用时才引入外部数据库。
- 部署消费者：保持 PEM 目录契约不变，在业务侧增加 reload watcher，而不是给 Agent 增加任意命令执行能力。
- 事件通知：显式配置 `ACME_ALERT_WEBHOOK_URL` 后，业务失败、证书到期和 Agent 离线事件先进入 SQLite 持久投递队列，再由独立工作者发送签名 Webhook，支持重试、租约恢复和人工重发。详见 [运维查询与通知](operations-and-notifications.md)。
