# 安全设计与运维边界

## 保护对象

高敏感数据包括：DNS AccessKey Secret、ACME 账户私钥、签发证书私钥、内部 Agent CA 私钥、管理员密码和有效会话。Acme4go 不把这些值写入日志或 API 列表响应。

## 静态加密

`ACME_MASTER_KEY` 通过 HKDF-SHA256 为不同用途派生 AES-256-GCM 密钥。密文格式包含版本、96 位随机 Nonce 和带认证密文；用途字符串作为附加认证数据，因此某一字段的密文不能被复制到另一字段后成功解密。

被加密的内容：

- DNS AccessKey ID 与 Secret；
- ACME 账户 P-256 私钥；
- 每一版本证书私钥；
- 内部 Agent CA 私钥。

Agent 使用本地生成的独立 32 字节主密钥加密下载缓存。客户端身份私钥本身以 `0600` 保存在持久化目录，因为它必须在无人值守重启时建立 mTLS；目录权限和主机访问控制是它的最终保护边界。

## 管理面

- 密码：Argon2id，随机盐，内存硬化参数。
- 会话：随机 256 位令牌，Cookie 使用 HttpOnly、SameSite=Strict；HTTPS 公开 URL 时自动添加 Secure。
- 数据库：仅保存会话令牌与 CSRF 令牌的 SHA-256 摘要。
- 改密并发：创建会话和修改密码时原子核对之前验证的密码摘要；改密后在途旧密码登录不能产生有效会话，旧改密请求也不能覆盖新密码。Argon2 计算在数据库事务之外进行。
- CSRF：所有非安全方法验证自定义 Token；浏览器带 Origin 时还要求与 `ACME_PUBLIC_URL` 或当前 HTTP 请求 Host 同源，因此本机可在 `localhost` 与 `127.0.0.1` 间切换而不会降低跨站校验。
- 私钥下载：额外要求 CSRF Token，设置 `Cache-Control: no-store`。
- 响应头：拒绝 MIME 猜测和 iframe，限制 Referrer 与 CSP。
- 错误：外部只返回稳定业务信息，底层 ACME、数据库和文件错误只进入服务端日志。
- 暴力破解：同一来源与账号组合在 15 分钟内连续失败 5 次后暂停登录 15 分钟，成功登录会清零计数；Argon2 同时计算数限制为 4，避免并发登录耗尽内存。
- 资源边界：同来源全部登录请求每分钟最多 30 次，成功登录不重置来源预算。用户名最多 256 字节，密码最多 1024 字节；超长字段在账号缓存和密码计算前拒绝。账号与来源缓存分别最多 4096 项，满载拒绝新键并保留有效封禁；账号键保存固定长度摘要，过期清理最多每分钟一次。共享代理或 NAT 的用户共同使用来源预算，应准确配置可信代理。

生产管理面应放在 HTTPS 反向代理后，并限制管理来源网段。代理需要保留 Host 与 HTTPS 语义，`ACME_PUBLIC_URL` 必须设置为浏览器实际使用的公开地址。只有 `ACME_TRUSTED_PROXY_CIDRS` 明确列出的代理来源才能提供 `X-Forwarded-For`、`X-Real-IP` 和 `X-Forwarded-Proto`；不要把该值配置成任意公网网段。

失败告警 Webhook 仅在显式配置时启用。生产接收地址必须使用 HTTPS，接收端应使用独立的 `ACME_ALERT_WEBHOOK_SECRET` 校验 `X-Acme4go-Signature`，不要把该 Secret 与部署主密钥复用。告警正文只包含事件类型、严重级别、资源标识和安全摘要，不包含凭据、令牌或私钥。

## Agent 面

Agent 端口直接提供由内部 CA 签发的 HTTPS 证书。首次注册不带客户端证书，但只能使用短期一次性 Token；其他路径必须提供有效客户端证书，并通过数据库中的 Agent UUID、序列号和启用状态检查。

每次 Agent 请求还会检查实际呈现证书的生效和到期时间。即使复用在证书有效期内建立的 TLS 长连接，证书过期后也会返回 403；身份轮换期间保留的旧序列号同样不能超出旧证书自身的有效期。

Agent 请求资源按节点和接口类别隔离：普通请求全局最多 6 个、单节点最多 2 个；心跳与身份续签另有全局 2 个、单节点 1 个的共享额度。单个节点不能占满任一类别，普通请求也不能借用关键接口额度。节点并发超限返回 `429 AGENT_CONCURRENCY_LIMITED`，类别额度耗尽返回 `503 AGENT_BUSY`，两者提供 `Retry-After: 1`。额度随请求退出释放，无在途请求的节点不保留计数记录。

身份查询使用独立的最多 8 个并发与 2 秒上下文期限，查询结束即释放，不跨越业务处理。Agent POST 请求（含注册）使用 HTTP 传输层 5 秒读取期限，HTTP/1.1 和 HTTP/2 均适用；期限从请求头完成、进入 Handler 时计算，原请求头读取保护仍保留。这里限制的是请求体读取，不是证书下载响应时间。该隔离防止单节点慢请求耗尽全体业务槽位，不代表可以抵御无限连接或多个恶意节点的协同流量。

不要在普通终端历史、工单或聊天中长期保存 Join URL。它虽然只能使用一次且十分钟过期，但在有效期内等同于一个 Agent 注册凭据。

Agent 的能力被约束为：

- 读取自己的期望目标；
- 下载明确分配给自己的证书；
- 上报自己的心跳与部署结果；
- 续签自己的客户端证书。

Agent 没有管理 API、DNS 凭据读取能力或其他 Agent 的证书读取能力。

## 明文运行副本

部署前和 Agent 磁盘复核均检查完整 PEM 链、链首与叶证书的一致性、签名顺序、有效期及服务端用途约束。支持正常省略根证书的 CA 链和自签测试证书；信任来源仍是已认证控制面的证书指纹，不强制使用系统公共根库。无效或损坏的 `fullchain.pem` 不会被当作完整部署。

Nginx、EMQX 等业务服务必须读取明文私钥，因此 `ACME_DEPLOYMENT_DIR` 是刻意存在的明文边界。建议：

- 使用独立目录，不要与控制面数据库目录混用；
- Acme4go Server 本机执行器或 Agent 对目录可写，业务容器只读挂载；
- 业务进程以与证书执行器相同的受控 GID 读取 `0640` 私钥；
- 不把部署目录上传到普通对象存储、构建产物或日志采集系统；
- reload watcher 只监控 `active.version` 或 `current` 变化，不给予 Agent Docker Socket。

## 主密钥轮换

`acme4go doctor` 只读打开已有数据库，不初始化数据库或运行迁移；检查已有内部 CA 的解密、属性、有效期和密钥配对，以及全部 DNS、ACME 账户密文、业务证书加密材料和已成功本机部署的文件。没有业务证书时，内部 CA 检查仍可识别错误主密钥。缺失或损坏身份材料会失败，不会生成或替换 CA；旧双文件 CA 格式只读取，不迁移。诊断不联系 CA、DNS 或其他外部服务，也不代表真实签发及服务加载验收。

当前版本没有在线主密钥轮换命令。主密钥必须与 `acme4go backup` 生成的数据归档成组保管，但不得放在同一个归档或同一权限域中。恢复后应先运行 `acme4go doctor`。若需要轮换，应在离线维护窗口实现“用旧密钥逐项解密、用新密钥重新加密、事务性替换”的专用流程；绝不能只修改环境变量后直接启动。

## 撤销与事件响应

- 管理员凭据泄露：修改密码会删除全部会话；同时检查审计日志并轮换 DNS 凭据。
- Agent 主机泄露：在控制台撤销 Agent，重新部署主机并创建新的注册信息。撤销不会删除已泄露主机上的文件，应同时轮换相关证书。
- DNS 凭据泄露：先在对应服务商禁用/轮换 AccessKey 或 Cloudflare API Token，再更新控制面记录。
- 主密钥泄露：攻击者还需要数据目录才能解密；按高严重度事件处置，同时轮换 DNS 凭据、ACME/证书材料和内部 CA。
- 内部 CA 泄露：停止 Agent 入口、替换数据目录中的 CA（当前需重新初始化）、撤销并重新注册所有 Agent。

## 明确不做的事情

- 不把 Agent 设计成远程 Shell；
- 不连接 SSH；
- 不挂载 Docker Socket；
- 不执行用户配置的任意 reload 命令；
- 不支持多个控制平面同时共享一个 SQLite 数据目录；
- 不把管理面和 Agent 面混在同一未加密监听端口。
