# 运维查询与通知

## 订单和证书查询

订单和证书页面的关键词、状态条件在后端作用于完整记录集，再执行分页。订单支持按编号精确查询；两个页面都支持域名、系列名称和系列编码搜索。证书列表的统计对应完整筛选结果，不受当前页大小影响。API 还支持 `seriesId` 条件。

同一系列最多存在一笔 `QUEUED` 或 `RUNNING` 订单。人工申请、失败重试和自动续期共用该约束，重复受理返回 HTTP 409。新系列只在凭据、域名授权校验通过后与订单一起提交，写入失败时事务完整回滚。已有系列继续使用其长期配置，修改联系邮箱或续期凭据应通过“证书系列”页面完成。

订单详情显示持久化阶段时间线，执行中每 5 秒刷新。事件只包含系统生成的阶段说明和安全错误摘要，不保存 DNS Secret、API Token、私钥或第三方原始响应。升级前的订单会增加“升级时记录的当前阶段”快照；不会补造不存在的历史事件。订单被保留期任务清理时，其事件一并删除。

## 到期观察与实际部署版本

首页和到期通知监控两类版本：

- 已启用证书系列的当前版本；
- 已启用部署目标最近一次成功使用的版本。

同一物理证书只统计一次。旧版本在成功替换后退出预警，仍可在证书资料库查询。如果系列已经续期但远端仍使用旧版本，旧版本继续参与到期预警。首页观察列表在完整监控范围内排序，不受历史版本分页影响；“证书库版本数”仍统计全部历史。

历史清理会保留每个启用目标最近一次成功回执，直到目标停用或删除，确保仍在使用的旧版本不会因审计记录清理而漏掉预警。

## Webhook 配置与投递

继续使用 `ACME_ALERT_WEBHOOK_URL` 和 `ACME_ALERT_WEBHOOK_SECRET`（或对应 `_FILE`）配置。Secret 至少 32 字节，生产接收地址必须是 HTTPS。没有配置 Webhook 时不创建或发送新通知，历史投递记录仍可查看。

“告警投递”页面支持状态筛选、分页、创建测试通知和重新发送失败通知。测试按钮只表示事件已入队，必须观察记录变为“已送达”来确认接收端成功响应。

订单失败、本机部署失败和 Agent 部署失败会将业务状态、历史及通知事件写入同一 SQLite 事务；通知入队失败时，业务变更一起回滚。服务关闭时等待已启动任务保存失败通知，启动恢复遗留订单时也会原子创建通知。通知未启用时只保存业务状态。

持久事件由独立工作者每 5 秒扫描发送。单次请求最多 10 秒；失败后从 15 秒开始指数退避，间隔最多 15 分钟，一轮最多尝试 8 次，包含发送结果未确认而恢复的租约。第八次租约到期仍未确认时进入 `FAILED`，不会发起第九次发送；人工重发重新开始计数。工作者采用一分钟租约，进程退出后可恢复尚未确认的发送。数据库备份包含待发送通知。完成投递同时核对次数和租约标识，旧工作者不能覆盖人工重发后的新租约。

发送状态为 `PENDING → SENDING → SENT`，失败时转为 `RETRY` 或 `FAILED`。这是至少一次投递：接收端已经处理但响应丢失时，系统仍会重试。因此接收端应使用正文 `id` 去重；同一事件重试时 `id` 和 `timestamp` 保持不变。

请求头 `X-Acme4go-Signature` 仍为 `sha256=<HMAC-SHA256>`，签名输入是原始 JSON 请求体，签名密钥是独立 Webhook Secret。只有 HTTP 2xx 被视为成功；禁止跟随重定向。事件载荷不包含投递队列内部状态或秘密。

当前事件包括：

| 类型 | 触发条件 |
|---|---|
| `certificate.order.failed` | 签发或续期订单失败 |
| `certificate.renewal.schedule_failed` | 自动续期订单无法创建 |
| `certificate.deployment.failed` | 本机或 Agent 部署失败 |
| `certificate.expiring` | 在用版本进入配置的续期窗口 |
| `certificate.expiry_critical` | 在用版本距离到期不超过七天 |
| `certificate.expired` | 在用版本已经过期 |
| `agent.offline` | 已启用 Agent 超过两分钟没有与控制面通信 |
| `system.notification.test` | 管理员发起通知连接测试 |

运维状态每分钟扫描。到期通知按证书、风险级别和 UTC 日期去重；风险升级时生成新通知。七天内临期和已过期提醒独立于自动续期窗口，即使 `ACME_RENEW_BEFORE=24h`，三天后到期的在用证书也会触发临期提醒。离线通知按 Agent、最近通信时间和 UTC 日期去重，撤销的 Agent 不告警。终态通知按 `ACME_HISTORY_RETENTION` 清理，未完成的投递保留。

## Agent 回执恢复

Agent 将未被控制面确认的最新目标回执保存到 `agent/state.json`。部署失败、下载失败和上报失败都使本轮对账返回失败，但不阻止其他目标继续处理。外层仍保存成功目标状态和待补报回执。

部署回执必须包含期望目标中的 `revision`。服务端在同一事务中检查目标修订、Agent 启用状态、目标和系列启用状态、当前证书及指纹，然后更新状态和历史。配置已变化的回执返回 HTTP 409；缺少修订号返回 HTTP 400。修改目录后，旧目录的成功回执不能把新目录标为成功。

证书文件已验证且落地成功时，即使成功回执丢失，下一轮或重启后也只补报结果，不重复下载同一版本。目标删除、配置修订或证书版本变化时，旧回执失效。全部目标和回执完成后才推进完整成功的期望状态修订。

曾上报失败的目标，即使文件随后由外部恢复，也会在重试到期且验证通过后补发成功回执并清理失败重试状态。恢复成功回执发送失败时持久化等待补报，重启后继续确认恢复，不会因为文件匹配旧成功快照就长期保留失败状态。

材料处理失败按目标独立退避，间隔从 30 秒增加到最多 5 分钟；配置或版本变化立即重新尝试。控制面连接失败仍使用部署轮询退避。

心跳是独立任务，启动时立即发送，此后固定每 30 秒发送，单次最多等待 10 秒。它不受 `ACME_AGENT_POLL_INTERVAL`、部署下载、磁盘物化或身份续签耗时影响。身份证书轮换后，心跳通过并发安全的客户端快照使用新证书。Server 在四个心跳周期（两分钟）未成功上报后判定离线。退出时取消心跳请求并等待其结束。

## 本机部署一致性

本机部署从读取当前目标和系列开始，到验证证书、物化文件及登记结果结束，与目标编辑/删除、系列设置和当前证书推进共享同一协调区间。历史物化目录清理也参与协调。变更请求等待正在执行的文件操作完成后提交，等待可以取消；普通数据库读取、Agent 心跳及通知投递不持有该协调权。当前采用单控制平面内的本机部署串行协调，不支持多个 Server 共享数据目录。

本机结果必须匹配执行时的目标修订、启用系列、当前证书及指纹。旧执行快照不能把新配置标成成功。文件已切换后的结果使用独立短上下文保存，避免浏览器断开导致结果丢失。

暂停部署目标只停止自动部署，仍允许管理员手动同步。停用证书系列会同时阻止本机自动和手动部署；已经开始的本机部署先完成，停用提交成功后不会再有旧任务继续物化。停用不删除已经存在的证书文件。

## Cloudflare 凭据

新增 DNS 凭据时选择 Cloudflare，填写根域名和 API Token，无需填写 AccessKeyId。Token 需要目标区域的 Zone Read 和 DNS Write 权限，服务端自动查询 Zone ID。编辑时 Token 留空保留原值，已有凭据的服务商不可切换；需要切换时新建凭据并修改证书系列配置。

“测试连接”会查询区域，在随机名称下创建临时 TXT 记录，再仅删除本次创建的记录。实际 ACME 签发复用 lego 的 Cloudflare Provider，支持普通域名和通配符；原阿里云凭据保持兼容。

Cloudflare 使用 Bearer API Token 创建和删除 DNS 记录的契约见 [创建记录 API](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/create/)、[删除记录 API](https://developers.cloudflare.com/api/resources/dns/subresources/records/methods/delete/) 和 [区域查询 API](https://developers.cloudflare.com/api/resources/zones/methods/list/)。

## 升级说明

本轮 Agent 并发隔离修复仅需更新 Server，不新增数据库迁移或 Agent 请求字段。已兼容当前回执协议的 Agent 可以继续使用。普通请求额度为全局 6 个、每节点 2 个，心跳与续签额度为全局 2 个、每节点 1 个；并发拒绝后按重试策略重新发送，不要并发重放。Agent POST 请求体须在进入 Handler 后 5 秒内发送完毕。其余历史协议升级要求仍见下文。

当前数据库契约版本为 **6**。新增版本记录 `portable_material_paths` 标记可迁移的相对证书材料路径，不批量改写既有记录。旧绝对路径在读取时按证书身份映射到当前数据目录；不读取原目录，也不在当前材料缺失时回退到旧目录。新程序可以读取两种格式，仅支持版本 5 的旧程序会拒绝打开版本 6 数据库。

登录字段上限为用户名 256 字节、密码 1024 字节，单来源每分钟最多 30 次登录请求；账号及来源缓存分别最多 4096 项。若历史管理员使用了超长凭据，需在升级前改为此边界内的凭据。共享 NAT 或代理下的用户共用来源预算，须正确配置可信代理以保留实际客户端地址。

完整证书链检查同时用于 Server 本机部署和 Agent 磁盘复核，因此两端都应更新才能获得完整保护。省略根证书的正常链仍受支持，损坏、错序、重复、过期或缺少颁发者的链会被拒绝；不改变既有 CA 信任来源。

Agent 部署回执要求必填 `revision`。Server 与 Agent 需要配套升级：更新 Server 后立即更新全部 Agent。在旧 Agent 更新前，其缺少修订的回执会被拒绝，不会更新部署成功状态。新 Agent 的回执也不保证被旧 Server 接受，不应长期混用两个协议版本。已保存的待补报回执含有目标快照，升级后的 Agent 可从中读取修订并继续对账。

数据库新增迁移 4（活动订单互斥、时间线）和迁移 5（DNS 服务商约束）。迁移 4 保留同系列最早的活动订单，将其他重复活动订单标记失败并保留历史；Server 随后的常规启动恢复仍会终结遗留未完成订单。迁移 5 保留 DNS 凭据主键、加密材料和所有引用，重建约束后检查外键，失败回滚。

升级前使用现有备份命令保存一致快照；升级到版本 6 后，回退旧程序必须恢复与之匹配的升级前备份，不能直接复用已升级数据库。


## 凭据的多根域名范围

一条 DNS 凭据可配置 1 至 100 个根域名。编辑凭据时每行填写一个，也支持中英文逗号或空白分隔；界面以标签预览，服务端统一小写、移除末尾点并去重。根域名不含协议、路径和通配符。例如配置 `example.com` 后允许申请 `example.com`、`*.example.com` 及其子域名。空列表不代表全部域名；仅启用云部署用途时可不填根域名。

- 同一条凭据可供多个独立证书系列使用，也可用于同一次跨根域名的证书申请。共用凭据不会自动合并已有证书。
- 根域名列表是本系统的 DNS 申请范围，密钥仍须拥有服务商侧对应域名的权限；该列表不限制或扩大 OSS/CDN 部署权限。
- 移除或缩小域名范围时，服务端在同一事务内检查所有引用系列（含停用系列）和活动申请。若仍有引用超出新范围，保存被拒绝并列出受影响名称。请先为这些系列更换 DNS 凭据，并等待原申请结束；停用系列本身不会解除引用。
- DNS 权限测试依次验证所有根域名的临时 TXT 创建与清理，一项失败仍继续其余项目。测试后打开凭据详情，展示每项状态、说明与时间；失败信息不包含原始服务商响应或密钥。每项查询与写入设置 45 秒超时，总测试按 5 分钟时限控制；已创建记录的清理使用独立的 20 秒时限，未完成项不会计为通过。
- 编辑凭据会清空旧测试状态。测试过程中配置发生变化时，旧结果不能覆盖新配置，需要重新测试。
- 多个域名共享密钥也共享轮换与失效影响；需要业务隔离时使用独立凭据。

数据库迁移版本 11 自动把已有单根域名扩展为列表，保留凭据主键、密文和证书引用。启动时自动迁移，无需手工 SQL；旧版本程序不能读取版本 11 的库，回退须使用升级前备份。

接口新增 `zones: string[]` 和只读 `lastTestResults`，保留 `zone` 为首个根域名。请求提供 `zones` 时以其为准；旧客户端编辑已有多根域名凭据，只要没有改变首域名就保留完整列表，不能通过单个 `zone` 静默删除其余域名。测试接口正常完成时返回 `success`、`message`、`testedAt`、`results`；部分域名失败属于正常测试结果（`success: false`），请求失败或配置过期仍返回错误。
