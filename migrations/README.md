# 历史数据库快照

本目录只保存早期数据库结构的历史快照，不是 Acme4go 的运行时迁移目录。应用不会扫描、排序或执行这里的 SQL 文件。

当前数据库演进流程为：

```text
internal/store/schema.sql
        │
        ├─ 新数据库：store.Open() 执行完整 Schema
        │
        └─ schema_migrations：查询已经成功完成的版本
                │
                └─ 只执行尚未记录的 Go 幂等迁移
```

其中：

- `internal/store/schema.sql` 是新数据库完整结构的唯一权威来源；
- `schema_migrations` 保存已经完整成功的版本、稳定名称和完成时间；
- `internal/store/migrations.go` 明确安排迁移版本与顺序；
- 各 Go 迁移函数负责识别并升级旧结构，必须允许重复执行，以覆盖迁移成功后、版本落库前进程退出的恢复窗口；
- 失败迁移不会写入完成记录，Server 会停止启动；
- 已登记版本不能被不同名称复用，旧二进制也会拒绝打开迁移版本更高的数据库；
- 最新数据库重复启动只读取版本记录并执行轻量结构守卫，不再重复归并历史数据或重建唯一索引；
- SQLite 不保存字段 `COMMENT` 元数据，表、字段、约束和索引说明统一维护在 `schema.sql` 源码注释中；
- `001_initial.sql` 早于证书系列模型，内容不代表当前完整结构，不得在生产数据库上手工执行。

新增或修改数据库结构时，必须同时完成以下工作：

1. 更新 `internal/store/schema.sql`，保证新建数据库直接得到最终结构；
2. 为已有数据库增加 Go 幂等迁移，并在 `internal/store/migrations.go` 中分配不可复用、单调递增的版本号；
3. 尽可能在事务内完成数据修复和约束建立；
4. 同时验证空数据库初始化、旧数据库升级、失败不记账以及最新数据库重复启动无结构写入；
5. 为表、字段、约束、索引以及迁移函数补充中文说明。

如果未来决定改用编号 SQL 迁移，必须先引入明确的迁移执行器、版本表、事务与失败恢复策略，不能直接假定本目录中的文件会被应用执行。
